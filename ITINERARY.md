# Device-saved itinerary beta

Choose Save to trip on a verified local offer, then open My trip. One trip per browser/origin stores up to 50 distinct offers over 1–14 days. Name, destination, optional first date and notes are saved explicitly. Each stop has an optional time/note, a day selector, same-day ordering controls and removal. Print/save as PDF uses the browser print dialog. This does not reserve any service, calculate savings or build an optimized route.

Only public source fields are copied into a versioned `dutyperks-trip-v1` localStorage record. No trip data is sent to Supabase, an API, analytics or another user. The prototype `/api/trips/generate` is no longer used by the plan page. Browser storage is per device/profile/origin: no cloud sync, and browser-data removal loses the trip. Updating the plan reads the latest stored record; storage events refresh other open tabs. Failed writes show an error rather than claiming success. Invalid existing data is not silently deleted or overwritten.

Saved copies are not live verification. Known expiry before today or the planned visit is flagged; old source checks prompt re-review. Links open official terms or current local search. A source may change or be withdrawn sooner, so every snapshot carries a recheck message. Directions use encoded venue name/city/state, not guessed coordinates, and users must confirm the exact entrance or tour meeting point. MWR resources and cruise program summaries have no save button because they are not necessarily physical itinerary destinations.

Maintenance: keep `SavedOffer` limited to public fields; update the storage version if the data model changes. Avoid changing the origin/production hostname without a migration plan for browser-saved trips. Corrupt storage can be inspected/recovered rather than automatically reset. Unit checks cover validation, privacy projection, duplicate/size limits, day ordering, dates, expiry and encoded directions. Preview and production checks should cover saving, reload persistence, day changes, ordering, removal, navigation and phone layout.
